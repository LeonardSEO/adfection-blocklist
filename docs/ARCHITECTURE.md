# Independent research and direct publication

Both repositories run the same standard-library research engine, with their own `research/project.json` policy. External community/published lists are a one-time frozen bootstrap, not a daily upstream feed.

`refresh.py` discovers names through CT certificate SANs (including standalone domains), DNS, existing public scan archives and project-specific asset requests. Asset discovery imports the request host, never the publisher merely loading an asset. It saves only the hostname, configured asset path and scan reference, stripping URL query tokens. The queue preserves unfinished work and prioritizes candidates and least-recently-attempted tasks. Only historical/admitted indicators expand CT pivots; unverified candidates get bounded DNS and root measurements.

`probe.py` performs root-only HTTP/TLS measurements on 80/443 or specific recently observed ports. It validates all DNS answers, pins numeric public addresses, rechecks redirects, rejects paths/queries/credentials, and enforces absolute subprocess deadlines. No exploits, login, browser scripts, mass scanning or port sweeps. The read-only measurement job receives no secrets or persistent git credentials.

`research/registry.json` preserves immutable observations, actual observation timestamps separately from collection times, relationships, source provenance and status. `publish.py` treats artifacts as data, cannot import trusted admission/status flags, and computes two publication tiers offline:

- Regular combined and discovered outputs: historical bootstrap and/or qualified detector admissions. Positive/negative/shadow qualification remains required for verified attribution. Disabled detectors withdraw only their findings.
- Opt-in `*-unverified.txt`, eight formats: automatically selected evidence-backed candidates; attribution remains unverified. `research/unverified.json` lists each rule/version, evidence IDs, anchor and evaluation time. This file is reproducibly checked against the register and current policy. These entries never silently enter the regular list and cannot recursively expand discovery.

Unverified v1 requires current (seven-day) public DNS and one of: an explicitly configured owned-root subdomain with a discovery/measurement record; the newest CNAME answer pointing at an exact configured dedicated target; a recent scan recording a successful 2xx JavaScript response (status, MIME type and body SHA256 retained) for a project-specific asset served by that host; or a matching live TLS certificate plus HTTP fingerprint on a known historical/admitted host. The last rule requires a non-generic, non-parking 2xx body of at least 64 bytes, separate same-session TLS/HTTP evidence on each host, and fresh evidence. Shared IP, ASN, NS or a certificate alone never qualifies. Latest private/NXDOMAIN answers, allowlist exclusions and withdrawn candidates are excluded. Evidence expires from this opt-in output, while observations and historical indicators remain intact. Root policies can be changed to retract a heuristic rule's candidates.

Daily runs (Adfection 06:17 UTC; Pegasus 06:47 UTC) have a 600-second research budget and support manual dispatch. Collection failures produce a partial report, not an empty-list replacement. A separate trusted write job validates the registry, tier evidence, unit tests, reproducible outputs and resolver syntax before committing generated data directly to `main`. No update PR is created. Pushes never use force; concurrent main changes fail safely and the archived artifact is retained for reprocessing. Main's required-status gate is removed for this explicitly requested direct-push model; deletion/force-push protections remain. Ordinary CI runs after explicit dispatch because GITHUB_TOKEN pushes do not trigger push workflows. Existing contribution/Dependabot PRs still use validated auto-merge.

No new runtime packages or research API secrets are required. `scripts/discover.py` in Adfection is a retained legacy CLI and is not used by scheduled automation.
