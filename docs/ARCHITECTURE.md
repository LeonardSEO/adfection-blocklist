# Independent research and direct publication

Both repositories run the same standard-library research engine, with their own `research/project.json` policy. External community/published lists are a one-time frozen bootstrap, not a daily upstream feed.

`refresh.py` discovers names through CT certificate SANs (including standalone domains), DNS, existing public scan archives and project-specific asset requests. Asset discovery imports the request host, never the publisher merely loading an asset. It saves only the hostname, configured asset path and scan reference, stripping URL query tokens. The queue preserves unfinished work and prioritizes candidates and least-recently-attempted tasks. Only historical/admitted indicators expand CT pivots; candidates get bounded DNS and root measurements.

`probe.py` performs root-only HTTP/TLS measurements on 80/443 or specific recently observed ports. It validates all DNS answers, pins numeric public addresses, rechecks redirects, rejects paths/queries/credentials, and enforces absolute subprocess deadlines. No exploits, login, browser scripts, mass scanning or port sweeps. The read-only measurement job receives no secrets or persistent git credentials.

`research/registry.json` preserves immutable observations, actual observation timestamps separately from collection times, relationships, source provenance and status. `publish.py` treats artifacts as data, cannot import trusted admission/status flags, and computes publication offline. Combined outputs contain the historical bootstrap and qualified detector admissions; discovered-only outputs contain qualified own findings. Positive/negative/shadow qualification remains required for admissions, and disabled detectors withdraw only their findings. Candidate evidence and the queue remain in the registry; there is no separate heuristic candidate blocklist.

Daily runs (Adfection 06:17 UTC; Pegasus 06:47 UTC) have a 600-second research budget and support manual dispatch. Collection failures produce a partial report, not an empty-list replacement. A separate trusted write job validates the registry, tier evidence, unit tests, reproducible outputs and resolver syntax before committing generated data directly to `main`. No update PR is created. Pushes never use force; concurrent main changes fail safely and the archived artifact is retained for reprocessing. Main's required-status gate is removed for this explicitly requested direct-push model; deletion/force-push protections remain. Ordinary CI runs after explicit dispatch because GITHUB_TOKEN pushes do not trigger push workflows. Existing contribution/Dependabot PRs still use validated auto-merge.

No new runtime packages are required. The separate shared Free API coordinator uses the two secrets described in `FREE-API.md`; direct measurements remain secret-free. `scripts/discover.py` in Adfection is a retained legacy CLI and is not used by scheduled automation.

The authenticated provider layer is centralized in Adfection to serialize both repositories’ shared account access. A write-only reservation job commits durable budgets first, a read-only provider job uses host-bound keys, and a separate publisher validates and exports compact public snapshots. Both collectors consume these observations without direct authenticated or anonymous urlscan calls. See `FREE-API.md`.
